Step 0

Notation

  • Hidden states \(X \in \mathbb{R}^{L\times U}\), latent \(C \in \mathbb{R}^{L\times D_c}\).
  • Concatenated weights \(W^{\text{Q}} \in \mathbb{R}^{U\times HD_k}\), \(W^{\text{UK}} \in \mathbb{R}^{D_c\times HD_k}\), \(W^{\text{UV}} \in \mathbb{R}^{D_c\times HD_v}\), \(W^{\text{O}} \in \mathbb{R}^{HD_v\times U}\).
  • \(W_{(h)}\): the column block of head \(h\). \(\mathrm{slice}_h\), \(\mathrm{concat}\): reshape operations.
  • RoPE: a rotation matrix \(\mathbf{R}_p\) applied to one token at position \(p\).
  • \(i\): query position (\(L_q = 1\) at decode) · \(j\): cached key/value position (\(L_{kv}\), e.g. 100K).
  • \(h\): head (\(H=128\)) · \(u\): model dim (\(5120\)) · \(c\): latent (\(D_c=512\)).
  • \(k, k'\): key dim (\(128\)) · \(d\): value dim (\(128\)) · \(r, m\): RoPE dim (\(D_r = 64\)).
  • Summation: a repeated index is summed. Left-hand-side rule: an index on the left is free and never summed.

Sizes are DeepSeek-V2's. Colors used below: \(\iF{h}\) free index, \(\iS{k}\) summed index, \(\iP{j}\) position index carried by RoPE.

Showdown 1

Multi-Head Latent Compression

A matrix has two slots. Heads and features must be flattened into one axis, then sliced back out:

\[ C = XW^{\text{DKV}} \in \mathbb{R}^{L\times D_c} \] \[ K_{\text{cat}} = C\,W^{\text{UK}} \in \mathbb{R}^{L\times HD_k}, \qquad K^{(h)} = \mathrm{slice}_h(K_{\text{cat}}) \] \[ V_{\text{cat}} = C\,W^{\text{UV}}, \qquad Q_{\text{cat}} = X\,W^{\text{Q}}, \qquad \text{then slice each per head} \]
Operationsmatrix product, reshape, per-head slicing

Every axis gets its own letter. All tokens and all heads in one line each:

\[ C_{jc} = X_{ju}\,W^{\text{DKV}}_{uc} \] \[ K_{jhk} = C_{jc}\,W^{\text{UK}}_{chk}, \qquad V_{jhd} = C_{jc}\,W^{\text{UV}}_{chd} \] \[ Q_{ihk} = X_{iu}\,W^{\text{Q}}_{uhk} \]
Operationsindex contraction

Read it straight off the indices: \(C_{jc}\) carries no \(h\). It is the tensor MLA wants to cache. RoPE is ignored until Showdown 3.

Showdown 2

Key & Value Absorption: Where Matrix Associativity Gives the Wrong Answer

Naive associativity on the concatenated weights:

\[ (XW^{\text{Q}})(CW^{\text{UK}})^\top = X\,\underbrace{W^{\text{Q}}\,(W^{\text{UK}})^\top}_{U\times D_c}\,C^\top \in \mathbb{R}^{L\times L} \]

✗ Wrong. The product runs over all \(HD_k\) columns, so the 128 heads are summed into a single score map.

Correct only per head, and value absorption suddenly needs an explicit sum over heads:

\[ S^{(h)} = X\big(W^{\text{Q}}_{(h)}\,W^{\text{UK}\top}_{(h)}\big)C^\top, \qquad O = \sum_{h=1}^{H}\big(P^{(h)}C\big)\big(W^{\text{UV}}_{(h)}W^{\text{O}}_{(h)}\big) \]
Operationsslice per head, transpose each slice, remember when \(h\) is summed

Key absorption (associativity on \(k\)):

\[ S_{i\iF{h}j} = X_{iu}\,\underbrace{\big(W^{\text{Q}}_{u\iF{h}\iS{k}}\,W^{\text{UK}}_{c\iF{h}\iS{k}}\big)}_{W^{\text{Q,eff}}_{uhc}}\,C_{jc} = \tilde{Q}_{ihc}\,C_{jc} \]

Value absorption (associativity on \(d\)):

\[ O_{iu} = P_{i\iS{h}j}\big(C_{jc}W^{\text{UV}}_{c\iS{h}d}\big)W^{\text{O}}_{\iS{h}du} = \underbrace{\big(P_{ihj}\,C_{jc}\big)}_{\tilde{O}_{ihc}}\,\underbrace{\big(W^{\text{UV}}_{chd}\,W^{\text{O}}_{hdu}\big)}_{W^{\text{O,eff}}_{chu}} \]
Operationsreordering scalar factors
Check the left-hand side for \(h\). \(S_{ihj}\) has \(h\), so \(h\) is free and never summed: only \(k\) contracts. \(O_{iu}\) has no \(h\), so \(h\) is summed, and only at the end, because both \(\tilde{O}_{ihc}\) and \(W^{\text{O,eff}}_{chu}\) carry it. The rule that makes the naive matrix version wrong makes this version impossible to get wrong.

Result: decode reads only \(C_{jc}\) from the cache. \(K_{jhk}\) and \(V_{jhd}\) are never formed.

Production note: merge the weights offline, or multiply online?
  • Offline merge. \(W^{\text{O,eff}}_{chu}\) has \(512\times128\times5120 \approx 335\)M parameters per layer, about 40 GB of extra BF16 weights over 60 layers (and prefill still needs the unmerged weights).
  • Online, same bracket order. With \(L_q = 1\), engines such as vLLM and newer SGLang keep the original weights and run two small batched matmuls: \(\big((P_{ihj}C_{jc})\,W^{\text{UV}}_{chd}\big)\,W^{\text{O}}_{hdu}\) and \(\big((X_{iu}W^{\text{Q}}_{uhk})\,W^{\text{UK}}_{chk}\big)\,C_{jc}\).
  • Either way, \(K_{jhk}\) and \(V_{jhd}\) never exist.
Showdown 3

Why RoPE Blocks Absorption

No single matrix product rotates every row of \(Q\) by a different angle. Papers write \(\mathrm{RoPE}(\cdot)\), or fall back to one token pair:

\[ S^{(h)}_{ij} = x_i^\top W^{\text{Q}}_{(h)}\,\mathbf{R}_i^\top\mathbf{R}_j\,W^{\text{UK}\top}_{(h)}\,c_j \]

\(\mathbf{R}_i^\top\) and \(\mathbf{R}_j\) look symmetric. Nothing shows that \(i\) is 1 token while \(j\) is 100K tokens, or that \(h\) sits right next to \(\mathbf{R}_j\).

Operationsper-token vectors, transposes, black-box \(\mathrm{RoPE}(\cdot)\)

RoPE is just a 3-index tensor \(R_{pmk}\) (position \(p\), rotated dim \(m\), input dim \(k\)):

\[ Q^{\text{rot}}_{ihm} = R_{imk}\,X_{iu}\,W^{\text{Q}}_{uhk}, \qquad K^{\text{rot}}_{jhm} = R_{jmk'}\,C_{jc}\,W^{\text{UK}}_{chk'} \] \[ S_{ihj} = Q^{\text{rot}}_{ihm}K^{\text{rot}}_{jhm} = X_{iu}\,W^{\text{Q}}_{uh\iS{k}}\;\iP{R_{(j-i),\,kk'}}\;W^{\text{UK}}_{ch\iS{k'}}\,C_{jc} \]

\(W^{\text{Q}}\) holds \(k\), \(W^{\text{UK}}\) holds \(k'\). The shared index that allowed absorption is gone.

Operationsindex contraction, renaming a dummy index
Detailed derivation (5 steps)
3.1 · RoPE on one vector
\[ \mathbf{q}^{\text{rot}}_i = \mathbf{R}_i\,\mathbf{q}_i \qquad \text{(one token at a time)} \]
\[ v^{\text{rot}}_m = R_{pmk}\,v_k \qquad \text{(}p\text{: position, } m\text{: rotated dim, } k\text{: input dim)} \]
3.2 · Rotate the query and the key
\[ \mathbf{q}^{(h)}_i = W^{\text{Q}\top}_{(h)}x_i, \qquad \mathbf{k}^{(h)}_j = W^{\text{UK}\top}_{(h)}c_j \]
\[ Q^{\text{rot}}_{ihm} = R_{imk}\,X_{iu}\,W^{\text{Q}}_{uhk}, \qquad K^{\text{rot}}_{jhm} = R_{jmk'}\,C_{jc}\,W^{\text{UK}}_{chk'} \] The key's input dim is named \(k'\) so the next product does not repeat \(k\) four times.
3.3 · Dot product, then reorder scalars
\[ S^{(h)}_{ij} = \big(\mathbf{R}_i\mathbf{q}^{(h)}_i\big)^\top\big(\mathbf{R}_j\mathbf{k}^{(h)}_j\big) = \mathbf{q}^{(h)\top}_i\,\mathbf{R}_i^\top\mathbf{R}_j\,\mathbf{k}^{(h)}_j \]
\[ S_{ihj} = \big(R_{imk}X_{iu}W^{\text{Q}}_{uhk}\big)\big(R_{jmk'}C_{jc}W^{\text{UK}}_{chk'}\big) \] \[ = X_{iu}\,W^{\text{Q}}_{uhk}\,\big(R_{imk}\,R_{jmk'}\big)\,W^{\text{UK}}_{chk'}\,C_{jc} \]
3.4 · The middle bracket is a relative rotation (where \((j-i)\) comes from)
Each \(2\times 2\) block of \(\mathbf{R}_p\) rotates by angle \(p\theta\). Transposing reverses the rotation (\(\mathbf{R}_i^\top = \mathbf{R}_{-i}\)), and composing two rotations adds their angles: \[ \mathbf{R}_i^\top\mathbf{R}_j = \mathbf{R}_{-i}\,\mathbf{R}_j = \mathbf{R}_{j-i} \]
Only \(R_{imk}\) and \(R_{jmk'}\) carry the summed index \(m\). Fix \(i, j\): \(R_{imk} = (\mathbf{R}_i)_{mk} = (\mathbf{R}_i^\top)_{km}\), so summing over \(m\) is matrix multiplication: \[ \sum_m R_{imk}\,R_{jmk'} = \big(\mathbf{R}_i^\top\mathbf{R}_j\big)_{kk'} = \big(\mathbf{R}_{-i}\,\mathbf{R}_j\big)_{kk'} = \big(\mathbf{R}_{j-i}\big)_{kk'} \equiv R_{(j-i),\,kk'} \] \((j-i)\) is just the position slot \(p\) of the same rotation tensor \(R_{p,\,kk'}\), evaluated at \(p = j - i\).
Step-by-step proof: why \(\mathbf{R}_i^\top\mathbf{R}_j = \mathbf{R}_{-i}\mathbf{R}_j = \mathbf{R}_{j-i}\) (\(2\times 2\) block & Euler's formula)

1. Transpose reverses the angle (\(\mathbf{R}_i^\top = \mathbf{R}_{-i}\)): each \(2\times 2\) diagonal block of \(\mathbf{R}_p\) rotates by \(p\theta\); transposing flips the \(\sin\) signs (\(\cos(-x)=\cos x,\ \sin(-x)=-\sin x\)):

\[ \mathbf{R}_i^\top = \begin{pmatrix}\cos(i\theta) & \sin(i\theta) \\ -\sin(i\theta) & \cos(i\theta)\end{pmatrix} = \begin{pmatrix}\cos(-i\theta) & -\sin(-i\theta) \\ \sin(-i\theta) & \cos(-i\theta)\end{pmatrix} = \mathbf{R}_{-i} \]

2. Composing rotations adds angles (\(\mathbf{R}_{-i}\mathbf{R}_j = \mathbf{R}_{j-i}\)): let \(\alpha = -i\theta,\ \beta = j\theta\) (so \(\alpha + \beta = (j-i)\theta\)) and multiply the \(2\times 2\) blocks entry by entry:

\[ \mathbf{R}_{-i}\,\mathbf{R}_j = \begin{pmatrix}\cos\alpha & -\sin\alpha \\ \sin\alpha & \cos\alpha\end{pmatrix}\begin{pmatrix}\cos\beta & -\sin\beta \\ \sin\beta & \cos\beta\end{pmatrix} = \begin{pmatrix}\cos\alpha\cos\beta - \sin\alpha\sin\beta & -(\cos\alpha\sin\beta + \sin\alpha\cos\beta) \\ \sin\alpha\cos\beta + \cos\alpha\sin\beta & \cos\alpha\cos\beta - \sin\alpha\sin\beta\end{pmatrix} \]

Applying \(\cos\alpha\cos\beta - \sin\alpha\sin\beta = \cos(\alpha+\beta)\) and \(\sin\alpha\cos\beta + \cos\alpha\sin\beta = \sin(\alpha+\beta)\):

\[ \mathbf{R}_{-i}\,\mathbf{R}_j = \begin{pmatrix}\cos\big((j-i)\theta\big) & -\sin\big((j-i)\theta\big) \\ \sin\big((j-i)\theta\big) & \cos\big((j-i)\theta\big)\end{pmatrix} = \mathbf{R}_{j-i} \]

1-line intuition (Euler's formula): a 2D rotation by \(p\theta\) is multiplication by \(e^{\mathrm{i}p\theta}\), so \(e^{-\mathrm{i}i\theta}\cdot e^{\mathrm{i}j\theta} = e^{\mathrm{i}(j-i)\theta}\). Because \(\mathbf{R}_p\) is block-diagonal, every entry \((k,k')\) satisfies \((\mathbf{R}_{-i}\mathbf{R}_j)_{kk'} = (\mathbf{R}_{j-i})_{kk'}\).

3.5 · Result
\[ S^{(h)}_{ij} = x_i^\top W^{\text{Q}}_{(h)}\,\mathbf{R}_{j-i}\,W^{\text{UK}\top}_{(h)}\,c_j \]\(h\) hides in a subscript; the sizes of \(i\) and \(j\) are invisible.
\[ S_{ihj} = X_{iu}\,W^{\text{Q}}_{uhk}\;\iP{R_{(j-i),\,kk'}}\;W^{\text{UK}}_{chk'}\,C_{jc} \]\(k\neq k'\): the chain between \(W^{\text{Q}}\) and \(W^{\text{UK}}\) is broken by a position-dependent factor.

The Fix: Decoupled RoPE

The paper concatenates a content part and a RoPE part for every head:

\[ \mathbf{q}_{t,h} = \big[\mathbf{q}^{C}_{t,h};\ \mathbf{q}^{R}_{t,h}\big], \qquad \mathbf{k}_{t,h} = \big[\mathbf{k}^{C}_{t,h};\ \mathbf{k}^{R}_{t}\big] \] \[ \mathbf{k}^{R}_{t} = \mathrm{RoPE}\big(W^{\text{KR}}\mathbf{h}_t\big) \]

Why the split is needed, and why \(\mathbf{k}^{R}_t\) loses its head subscript, has to be explained in prose.

Separate the two clashing key-side operations into two branches:

\[ S_{ihj} = \tfrac{1}{\sqrt{D_k + D_r}}\Big(\underbrace{\tilde{Q}_{ihc}\,C_{jc}}_{\text{nope: } W^{\text{UK}} \text{ absorbs (no } R_j\text{)}} + \underbrace{Q^{\text{rope}}_{ihm}\,K^{\text{rope}}_{jm}}_{\text{rope: has } R_j,\ \text{shared key (no } h\text{)}}\Big) \] \[ Q^{\text{rope}}_{ihm} = R_{imr}\,X_{iu}W^{\text{QR}}_{uhr}, \qquad K^{\text{rope}}_{jm} = R_{jmr'}\,X_{ju}W^{\text{KR}}_{ur'} \]

Result: neither cached tensor (\(C_{jc}\) or \(K^{\text{rope}}_{jm}\)) carries \(h\). Content keeps per-head \(W^{\text{UK}}\) because \(R_j\) is gone; position keeps \(R_j\) without blowing up cache size because \(K^{\text{rope}}_{jm}\) drops \(h\).

Why sharing \(K^{\text{rope}}_{jm}\) across heads does not cost quality
  • \(h\) is still free on the left. In \(S^{\text{rope}}_{i\iF{h}j} = Q^{\text{rope}}_{i\iF{h}m}K^{\text{rope}}_{jm}\), every head reads the shared position key with its own query, so each head still gets its own distance pattern. The content keys \(K_{jhk}\) and values \(V_{jhd}\) keep their full \(h\).
  • What and where separate cleanly. Inside softmax the sum becomes a product: \(P_{ihj} \propto \exp\big(S^{\text{nope}}_{ihj}\big)\times\exp\big(S^{\text{rope}}_{ihj}\big)\): a position-independent content match times a relative-distance gate.
Showdown 4

Hardware: Count the Missing \(h\)

Prefill and decode are described as two procedures. Cache size has to be read from shape annotations, and code needs .view() / .transpose() to match.

A cached tensor costs one number per combination of its indices: drop \(h\) and the cache shrinks by \(H\). Prefill and decode are the same expression with different brackets, and the indices copy straight into torch.einsum.

Prefill

Decode

Load each \(C_{jc}\) once and reuse it across all 128 heads. 4× more math over \(c = 512\), but decode waits on memory, not compute.
Why is prefill compute-bound while decode is memory-bound?
  • Prefill (large \(L_q\), e.g. 4,096 tokens at once): each weight or key loaded from HBM is reused across thousands of tokens, so the GPU's Tensor Cores run full speed and compute is the limit.
  • Decode (\(L_q = 1\) token at a time): in standard MHA, every cached \(K_{jhk}\) loaded from HBM is used for just 1 query and 1 head, leaving compute mostly idle while waiting on HBM reads. Absorbed MLA loads \(C_{jc}\) once and reuses it across all 128 heads.

The index strings are the code: einsum("uhk,chk->uhc", W_q, W_uk), einsum("bihc,bjc->bihj", Q_tilde, C_kv). See verify_mla_absorption.py (float64, matches to 1e-10).
