01
Why it matters

Matrix calculus stops scaling at 2D

Key idea
Write one number at a time — \(Q_{\textcolor{#0969da}{i}\textcolor{#d4580a}{k}}\) — and ordinary scalar algebra works for tensors of any rank.
Matrix calculus
\[ D = \mathrm{rowsum}\big(P \odot (\bar{O}\,V^{\top})\big) \]
Transposes, \(\odot\), \(\mathrm{diag}\), \(\mathrm{Tr}\) — and no clean way to write 4D.
Einstein notation
\[ D_{\textcolor{#0969da}{i}} = P_{\textcolor{#0969da}{i}\textcolor{#d4580a}{m}}\,\bar{O}_{\textcolor{#0969da}{i}\textcolor{#d4580a}{d}}\,V_{\textcolor{#d4580a}{m}\textcolor{#d4580a}{d}} = O_{\textcolor{#0969da}{i}\textcolor{#d4580a}{d}}\,\bar{O}_{\textcolor{#0969da}{i}\textcolor{#d4580a}{d}} \]
Just regroup scalars. This one line is the FlashAttention backward trick.
◇

Represent

Every axis gets a name. 4D tensors read as clearly as 2D.

⇄

Derive

Regroup sums to discover new algorithms (Linear Attn, MLA).

∂

Differentiate

Chain rule + \(\delta_{ij}\) gives gradients at any rank.

Hardware

Index count reveals HBM vs. SRAM; free indices map to threads.

Wait — what about upper/lower indices (covariant / contravariant) from physics?

You don't need them for 99% of LLM math — and it's not a shortcut.

General relativity works in curved spaces and non-orthogonal coordinates, so it needs upper/lower indices and a metric tensor \(g_{\mu\nu}\) to stay coordinate-invariant.

LLM tensor ops (Attention, MLP, MoE, MLA, RoPE) live in flat Euclidean space with an orthonormal basis, where the metric is just the identity \(\delta_{ij}\). Upper and lower indices are numerically identical, so writing everything as subscripts loses zero information.

02
The rules

Three rules are all you need

1

Scalar view

A tensor is one indexed number.

\( Q_{\textcolor{#8250df}{b}\textcolor{#8250df}{h}\textcolor{#0969da}{i}\textcolor{#d4580a}{k}} \in \mathbb{R} \)
2

Repeated ⇒ summed

Not on the left-hand side and repeated ⇒ sum over it.

\( C_{\textcolor{#0969da}{i}\textcolor{#0969da}{j}} = A_{\textcolor{#0969da}{i}\textcolor{#d4580a}{k}}B_{\textcolor{#d4580a}{k}\textcolor{#0969da}{j}} \)
3

Order doesn't matter

Factors commute, so transposes disappear.

\( Q_{\textcolor{#0969da}{i}\textcolor{#d4580a}{k}}K_{\textcolor{#0969da}{j}\textcolor{#d4580a}{k}} = K_{\textcolor{#0969da}{j}\textcolor{#d4580a}{k}}Q_{\textcolor{#0969da}{i}\textcolor{#d4580a}{k}} \)

03
Conventions

Look at the left-hand side

Key idea
If an index is on the left-hand side, it is never summed, even when it repeats on the right.
\[ P_{\textcolor{#0969da}{i}\textcolor{#0969da}{j}} = \frac{\exp(S_{\textcolor{#0969da}{i}\textcolor{#0969da}{j}})}{\ell_{\textcolor{#0969da}{i}}} \]
i is on the LHS → free not summed
No LHS? Mark it with parentheses: \( D_{\textcolor{#0969da}{(i)}}\,dP_{\textcolor{#0969da}{(i)}\textcolor{#0969da}{j}} \)
Give every axis a fixed letter
b hBatch, head
iQuery position
jKey / value position
kQ·K head dim
dValue / output dim
m nInner sums (never reuse j)
Self-check: is it summed?
\( D_{i} = P_{im}\,dP_{im} \) — which index is summed?
m summed i free (on LHS)
\( s = A_{ij}B_{ij} \) — which indices are summed?
i, j both summed — this is \(\mathrm{Tr}(A^\top B)\).

04
Payoff

Linear attention is one regrouping

Key idea
Same three scalars, different parentheses — regrouping which index you sum first collapses \(O(L^2 D)\) to \(O(L D^2)\).
Sequence length L = 4,096 D = 64
Sum k first · O(L²D)
Sum j first · O(LD²)
05
Bonus · Learning Workflow

Agent Skill + Beginner Cheatsheet

Prompt
“Derive multi-head attention forward and backward.”
Without skill
Q' = Q.transpose(1, 2)
S  = Q' @ K'.transpose(-2, -1) / sqrt(D)
dS = P * (dP - (dP*P).sum(-1, keepdim=True))
dK = dS.transpose(-2, -1) @ Q' / sqrt(D)
# ...transpose(1, 2) back?
  • Axis order lives in your head
  • Easy to get transposes wrong
With tensor-index-convention
S_bhij  = Q_bhik K_bhjk / sqrt(D)
O_bhid  = P_bhij V_bhjd
D_bhi   = O_bhid dO_bhid
dS_bhij = P_bhij (dP_bhij - D_bhi)
dK_bhjk = dS_bhij Q_bhik / sqrt(D)
  • Every axis named, zero transposes
  • Readable scalar algebra at a glance
